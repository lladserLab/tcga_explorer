# TCGA-TRACE Implementation Report

Generated: 2026-04-25  
Updated: 2026-07-25

## Summary

This historical implementation report tracks the Dockerized survival-analysis
web application that is now named TCGA-TRACE. The current application provides
endpoint-aware TCGA transcriptomic survival workflows with Kaplan-Meier plots,
Cox models, proportional-hazards diagnostics, RMST, cutpoint sensitivity and
reproducible run exports.

The current scope is deliberately narrow and reproducible:

- TCGA RNA-seq cancer cohorts.
- TCGA-CDR clinical endpoints when a configured CDR file is mounted and endpoint QC passes.
- OS fallback derived from TCGA clinical/sample metadata when TCGA-CDR is not configured.
- Gene expression grouping from selectable, data-backed RNA bulk scales.
- Kaplan-Meier, Cox, PH diagnostics and RMST generated by R with the `survival`, `survminer` and `survRM2` ecosystem. Marker-specific PH cautions trigger a fixed two-year early/late Cox summary with explicit support rather than deleting the model.
- PNG, SVG, CSV, JSON, REMARK-style methodology TXT, audit HTML/JSON and ZIP output artifacts per analysis.

## Architecture

Services are defined in `docker-compose.yml`:

- `frontend`: Vite React app served by Nginx on `localhost:3000`.
- `backend`: FastAPI app on `localhost:8000`.
- `updater`: on-demand Docker service for weekly TCGA RNA-seq and TCGA-CDR synchronization.
- `postgres`: PostgreSQL 16 for cohort catalog, sample metadata, analysis jobs, and artifact references.

The frontend Nginx proxy forwards same-origin `/api` requests to FastAPI with 600-second connect, send, and read timeouts. This was added after validating that first-time RNA cache generation for large cohorts can exceed the default Nginx upstream timeout and otherwise surface as a browser-visible `Gateway Time-out`.

Docker Compose now also gates the frontend behind the backend healthcheck. On a fresh startup, FastAPI first imports metadata and preloads all RNA caches; only after `/api/health` reports a ready cache does Compose start the frontend container.

The TCGA data directory is mounted read-only:

```text
/mnt/data1/Andres/TCGA:/data/tcga:ro
```

Analysis artifacts are mounted into:

```text
./artifacts:/app/artifacts
```

Optional clinical data mount:

```text
./clinical:/app/clinical:ro
```

`TCGA_CDR_PATH` defaults to `/app/clinical/TCGA-CDR-SupplementalTableS1.xlsx`. The backend also accepts TSV/CSV equivalents with the TCGA-CDR endpoint columns.

## Incremental Data Sync

The project now includes an incremental updater instead of full duplicate snapshots. The canonical TCGA RNA-seq directory remains `/mnt/data1/Andres/TCGA`; sync state is stored under `/mnt/data1/Andres/TCGA/.sync`, while TCGA-CDR sync state is stored under `./clinical/.sync`.

Updater commands:

- `docker compose run --rm updater check --source all`
- `docker compose run --rm updater apply --source all --max-workers 10 --reimport`
- `scripts/weekly_tcga_update.sh`

The updater uses the GDC API for TCGA STAR-count manifests and the official TCGA-CDR publication manifest. It compares file IDs, md5 checksums, sizes, update timestamps, and data releases against the current local manifest. Changed files are downloaded into staging, validated, promoted atomically into the existing directory, and replaced files are copied to `.sync/backups/<run_id>/`.

For affected RNA cohorts, the updater updates the relevant `count_matrix.tsv` columns and `col_data.tsv` rows, rebuilds `summary_table.tsv`, invalidates derived RNA caches for those cohorts, and lets backend startup rebuild caches before the frontend becomes available. TCGA-CDR is validated for OS/PFI/DFI/DSS columns before promotion.

New audit tables:

- `data_manifests`: source, manifest hash, data release, data-through date, file count, manifest path.
- `data_sync_runs`: run id, source, status, start/end timestamps, changes, errors.

New API:

- `GET /api/data-sync/status`

Analysis request hashes now include the current data version, so completed KM jobs are not reused across data updates.

## Backend

The backend imports lightweight metadata into PostgreSQL:

- cohort rows from `summary_table.tsv`;
- sample-level records from each `TCGA-*/col_data.tsv`;
- OS fields derived from clinical/sample metadata;
- optional TCGA-CDR endpoint rows into a separate `clinical_endpoints` table;
- source status rows into a `data_sources` table;
- gene indexes lazily from `count_matrix.tsv`.

Large expression matrices are not imported into PostgreSQL. Startup cache warmup builds derived cache files instead:

- gene indexes in PostgreSQL for every cohort;
- sample library sizes for `log2(CPM + 1)`;
- GDC barcode-to-file maps for every cohort;
- binary gene-by-sample matrices under `./derived/rna_bulk/matrices` for `log2(TPM + 1)`, `log2(FPKM + 1)`, and `log2(FPKM-UQ + 1)`.

At analysis time, TPM/FPKM/FPKM-UQ expression lookup reads a single binary row for the requested gene instead of scanning all sample-level GDC STAR-count files. `log2(CPM + 1)` remains computed from `count_matrix.tsv` using preloaded library sizes.

Public API endpoints:

- `GET /api/health`
- `GET /api/cohorts`
- `GET /api/cohorts/{cohort}/genes?query=TP53`
- `GET /api/cohorts/{cohort}/filters`
- `GET /api/cohorts/{cohort}/endpoints`
- `GET /api/data-sources`

## Clinical Endpoints And Survival Analysis

When TCGA-CDR is mounted, the backend imports OS, PFI, DFI and DSS patient-level endpoint records and exposes them per cohort only when at least 10 linked patients and 5 events are available. Endpoint options are cohort-specific and disabled options carry the QC reason in the API and frontend.

When TCGA-CDR is not mounted, overall survival remains available as a fallback derived as:

- event = 1 when `vital_status == Dead`;
- event = 0 when `vital_status == Alive`;
- time = `days_to_death` for deceased patients;
- fallback time = `days_to_last_follow_up`, then `days_to_last_known_disease_status`;
- rows with missing or non-positive OS time are excluded.
- analyses retain one eligible RNA-seq sample per TCGA participant before fitting KM/Cox models; when several barcodes are available, the app prioritizes primary tumor or primary blood-derived cancer samples, then recurrent/additional/metastatic tumor samples, then normal/control samples only if no higher-priority sample remains after user filters; remaining ties are resolved by RNA analyte/portion metadata and barcode.

Supported cutpoints:

- maxstat cutpoint via `survminer::surv_cutpoint`, using maximally selected rank statistics with `minprop = 0.15`;
- median;
- tertiles;
- upper quartile vs rest;
- upper quartile vs lower quartile, discarding the middle 50%;
- custom percentile.

R plotting/statistics:

- `survival::Surv`;
- `survival::survfit`;
- `survival::survdiff`;
- `survival::coxph` for two-group hazard ratio;
- `survminer::surv_cutpoint` for maxstat stratification;
- `survminer::ggsurvplot` for Kaplan-Meier plot and risk table;
- `svglite` for on-demand SVG export.

Plot style options are sent with each analysis request and are included in the cache hash:

- group color palette as hex colors;
- font family (`sans`, `serif`, `mono`);
- base font size from 8 to 20;
- axis tick-label font size from 6 to 24;
- axis title font size from 6 to 26;
- plot grid visibility;
- optional plot title;
- plot X-axis unit (`days`, `months`, or `years`).

Each completed analysis also writes a parameter-specific REMARK-style `methodology.txt` artifact. This text is generated from the actual request payload, data snapshot dates, selected endpoint, endpoint source, selected expression scale, cutpoint method, filters, plot options, result metrics, warnings, limitations, and software versions. It is intended as a methods-section starting point for manuscripts and supplements.

To reduce initial plot-generation latency, the backend renders PNG immediately for display and defers SVG rendering until the user downloads SVG. CSV and methodology TXT are still produced with the analysis.

These choices mirror common TCGA survival-analysis tools such as GEPIA, UALCAN, UCSC Xena, OncoLnc, and KM Plotter, while keeping the v1 implementation reproducible and traceable.

## RNA Bulk Expression Audit

An RNA bulk transformation inventory was added in `docs/RNA_BULK_TRANSFORMATIONS.md` after inspecting the TCGA cohort data snapshot. The app exposes survival-oriented log-scale choices: `log2(TPM + 1)`, `log2(CPM + 1)`, `log2(FPKM + 1)`, and `log2(FPKM-UQ + 1)`. TPM/FPKM values are read from the original GDC cache during startup and materialized as derived binary matrices under `./derived/rna_bulk/matrices` after barcode alignment checks. Raw count, VST and rlog options are not exposed as direct survival expression scales; z-scoring is used for signature scoring and pan-cancer Cox, not as a standalone matrix scale.

## Frontend

The frontend is in English and optimized as an analysis workspace rather than a landing page.

Main workflow:

1. Select cancer cohort.
2. Select a survival endpoint available for that cohort.
3. Search/select gene symbol.
4. Choose cutpoint method.
5. Apply core clinical filters.
6. Run analysis.
7. View KM plot, p-value, HR, group counts, warnings.
8. Download PNG, SVG, CSV, methodology TXT, or a ZIP bundle.

Available filters:

- sample type;
- stage;
- gender;
- race;
- min/max age.
- maximum follow-up time.

## Gallbladder Data Note

The current TCGA cohort summary does not include a dedicated gallbladder cancer cohort. The closest available cohort is `TCGA-CHOL`, described as cholangiocarcinoma/biliary tract with 44 RNA samples and 36 paired patients. It includes intrahepatic and extrahepatic bile duct records and broader biliary tract metadata, but it should not be labeled as a pure gallbladder cohort.

## Limitations

- Full TCGA expression matrices are not redistributed in git; reviewers need a
  local TCGA snapshot or must materialize public GDC STAR-count files with the
  updater.
- The application currently covers bulk TCGA transcriptomes only; GTEx, GEO and
  other external validation cohorts are outside the current scope.
- Signature scoring uses transparent mean, z-score and weighted z-score modes;
  it is not a pathway-inference replacement for ssGSEA-style tools.
- RPPA and other non-RNA modalities are not exposed yet.
- The first full Docker startup after clearing `./derived` can take tens of minutes because all cohort expression caches are built before the frontend starts.
- The derived RNA matrix cache currently stores three GDC-based log scales; `log2(CPM + 1)` uses preloaded library sizes and still reads the requested count row from `count_matrix.tsv`.
- Maxstat is useful for exploration but should be interpreted with selection-bias awareness.
